# Barramento de Endereços
## 1. Introdução

Na aula anterior, conhecemos o **Barramento de Dados** — a estrada principal por onde a informação trafega dentro do computador. Vimos que, quanto mais larga essa estrada, mais dados podem viajar simultaneamente, e mais rápido o sistema se torna.<br><br>

Mas existe um problema: de nada adianta ter uma rodovia larga e veloz se os veículos não souberem para onde ir. Imagine uma cidade onde todos os caminhões saem do depósito carregados de mercadorias, mas não há placas indicando qual rua seguir. Os caminhões andariam sem destino, e a cidade entraria em colapso.<br><br>

No computador, a situação é análoga. O barramento de dados transporta os bits, mas **precisa de um guia** que diga: *"este dado deve ir para a posição 0x1000 da memória"* ou *"leia o dado que está na posição 0x2000"*.<br><br>

Esse guia é o **Barramento de Endereços**.<br><br>

O barramento de endereços é o sistema de sinalização do computador — ele diz **onde** os dados devem ser lidos ou escritos. Sua largura determina **quantas posições de memória** podem ser endereçadas, e portanto, o limite máximo de memória que o sistema pode suportar.<br><br>

Nesta aula, vamos explorar como o barramento de endereços funciona, como sua largura define a capacidade máxima de memória, e por que ele é essencial para que a CPU encontre as instruções e os dados de que precisa.<br><br>


## 2. O Que é o Barramento de Endereços?

### 2.1 Definição

O **Barramento de Endereços** é o conjunto de fios que transporta os **endereços** gerados pela CPU para a memória e para os dispositivos de entrada/saída.

### 2.2 Características principais

| Característica | Descrição |
|----------------|-----------|
| **Largura** | Número de bits do endereço (16, 20, 32, 64 bits) |
| **Direção** | **Unidirecional** (da CPU para a memória/periféricos) |
| **Função** | Indicar qual posição de memória ou dispositivo será acessado |
| **Capacidade** | 2ⁿ posições endereçáveis (onde n = largura do barramento) |

### 2.3 A analogia do carteiro

Pense no barramento de endereços como um **carteiro** que entrega cartas:

- O carteiro precisa saber o **endereço** de cada casa (barramento de endereços).
- A carta em si é o **dado** (barramento de dados).
- O carteiro só entrega a carta se o destinatário estiver em casa (barramento de controle).

Sem o endereço, a carta não chega a lugar nenhum.

## 3. Largura do Barramento de Endereços

### 3.1 Capacidade de endereçamento

A largura do barramento de endereços determina **quantas posições de memória podem ser endereçadas**:

> **Capacidade = 2ⁿ posições (onde n = número de bits do barramento de endereços)**

| Largura (bits) | Posições endereçáveis | Capacidade máxima (bytes) |
|----------------|----------------------|---------------------------|
| 8 | 2⁸ = 256 | 256 bytes |
| 16 | 2¹⁶ = 65.536 | 64 KB |
| 20 | 2²⁰ = 1.048.576 | 1 MB |
| 24 | 2²⁴ = 16.777.216 | 16 MB |
| 32 | 2³² = 4.294.967.296 | 4 GB |
| 36 | 2³⁶ = 68.719.476.736 | 64 GB |
| 64 | 2⁶⁴ = 18.446.744.073.709.551.616 | 16 EB (exabytes) |

### 3.2 Exemplo prático

**Problema:** Um processador tem barramento de endereços de **24 bits**. Qual a quantidade máxima de memória que ele pode endereçar?

**Cálculo:** 2²⁴ = 16.777.216 posições = **16 MB**

**Resposta:** O processador pode endereçar até **16 MB** de memória.

### 3.3 Analogia

Pense no barramento de endereços como um **número de CEP**:

- **8 bits (256 CEPs):** Uma pequena vila.
- **16 bits (65.536 CEPs):** Uma cidade média.
- **32 bits (4,29 bilhões de CEPs):** O mundo inteiro.
- **64 bits (18,4 quintilhões de CEPs):** Milhares de galáxias.

Quanto mais bits, mais endereços distintos podem ser representados.


## 4. Relação Entre Barramento de Dados e Endereços

### 4.1 Dois barramentos, duas funções

| Barramento | Função | Direção | Largura típica |
|------------|--------|---------|----------------|
| **Dados** | Transportar dados | Bidirecional | 8, 16, 32, 64 bits |
| **Endereços** | Indicar onde | Unidirecional | 16, 20, 32, 64 bits |

### 4.2 Por que são separados?

1. **Performance:** A CPU pode enviar um endereço enquanto recebe dados simultaneamente.
2. **Simplicidade:** Cada barramento tem sua função específica.
3. **Escalabilidade:** A largura de cada um pode ser ajustada independentemente.

## 6. Memória Endereçável

### 6.1 O que é memória endereçável?

**Memória endereçável** é a quantidade total de posições de memória que um processador pode acessar, determinada pela largura do barramento de endereços.

### 6.2 Limitações práticas

Na prática, a memória máxima endereçável pode ser limitada por:

1. **Barramento de endereços:** O limite teórico (2ⁿ).
2. **Controlador de memória:** Pode suportar menos do que o barramento permite.
3. **Sistema operacional:** Pode limitar o uso da memória (ex: 32 bits vs 64 bits).

### 6.3 Exemplo: Windows e memória

| Versão do Windows | Arquitetura | Memória máxima suportada |
|-------------------|-------------|--------------------------|
| Windows 7 32-bit | 32 bits | 4 GB |
| Windows 7 64-bit | 64 bits | 192 GB |
| Windows 10 64-bit | 64 bits | 2 TB |
| Windows Server 2019 | 64 bits | 24 TB |


## 7. Endereçamento de Periféricos

### 7.1 Mapeamento de memória vs I/O

Os dispositivos de entrada/saída também precisam de endereços.

| Método | Como funciona | Exemplo |
|--------|---------------|---------|
| **Memory-mapped I/O** | Periféricos ocupam endereços de memória | ARM, PowerPC |
| **Port-mapped I/O** | Periféricos têm endereços separados | x86 (IN/OUT) |

<details>
<summary>📗 Exercício 7 — Barramento de endereços x dados (conceitual)</summary>

<details>
<summary>💡 Ver resposta</summary>

**Resposta:** Porque cada barramento tem uma função diferente:
- **Dados:** Transporta os dados em si (bidirecional).
- **Endereços:** Transporta o destino dos dados (unidirecional).

Separar os barramentos permite que a CPU envie um endereço enquanto recebe dados simultaneamente, melhorando o desempenho.
