# Registradores de Uso Geral

## 1. Introdução

Nas últimas aulas, exploramos os registradores especializados da CPU: o **PC** (Contador de Programa), que aponta para a próxima instrução; o **IR** (Registrador de Instrução), que guarda a instrução atual; o **MAR** (Registrador de Endereço de Memória), que segura o endereço a ser acessado; e o **MBR** (Registrador de Buffer de Memória), que armazena os dados em trânsito entre a CPU e a memória.<br><br>

Todos esses registradores têm funções específicas e essenciais. Mas há um outro tipo de registrador que é igualmente importante: os **Registradores de Uso Geral** (também chamados de *General-Purpose Registers*).<br><br>

Se os registradores especializados são como funcionários dedicados a tarefas específicas (o carteiro, o entregador, o arquivista), os registradores de uso geral são como **caixas de ferramentas** — armários onde a CPU guarda dados temporários, operandos e resultados de operações. São a "mesa de trabalho" do processador.<br><br>

Pense neles como o **balcão de um marceneiro**:

- O marceneiro (CPU) tem várias ferramentas (ULA, UC).
- Ele precisa de uma superfície (registradores) para colocar as peças (dados) enquanto trabalha.
- Ele pode colocar qualquer peça em qualquer lugar do balcão (uso geral).
- Quanto maior o balcão, mais peças ele pode manipular ao mesmo tempo.

Os registradores de uso geral são o **armazenamento de dados mais rápido** da CPU. Eles são usados para:

- Armazenar operandos para operações da ULA.
- Guardar resultados intermediários.
- Manter variáveis frequentemente acessadas.
- Passar parâmetros entre funções.

Nesta aula, vamos explorar os registradores de uso geral: como eles funcionam, como são organizados, e por que são tão importantes para o desempenho do processador.


## 2. O Que São Registradores de Uso Geral?

### 2.1 Definição

**Registradores de Uso Geral** (RUG) são registradores da CPU que:

> **Não têm função fixa — podem ser usados para armazenar qualquer dado temporário, operando ou resultado durante a execução de instruções.**

### 2.2 Características principais

| Característica | Descrição |
|----------------|-----------|
| **Tamanho** | Igual à palavra do processador (8, 16, 32, 64 bits) |
| **Quantidade** | Varia conforme a arquitetura (8 a 32 registradores) |
| **Função** | Armazenamento temporário de alta velocidade |
| **Acesso** | Muito rápido (1 ciclo de clock) |
| **Uso** | Operandos, resultados, variáveis, parâmetros |

## 3. Tipos de Registradores

### 3.1 Registradores de Uso Geral vs Especializados

| Tipo | Exemplos | Função |
|------|----------|--------|
| **Uso Geral** | R0, R1, R2, ... | Qualquer dado temporário |
| **Especializados** | PC, IR, MAR, MBR | Funções específicas |

### 3.2 Registradores com funções sugeridas

Em algumas arquiteturas, os registradores têm usos sugeridos (mas não obrigatórios):

| Arquitetura | Registrador | Uso sugerido |
|-------------|-------------|--------------|
| **ARM** | R0-R3 | Parâmetros de função |
| **ARM** | R4-R11 | Variáveis locais |
| **ARM** | R13 (SP) | Ponteiro de pilha |
| **ARM** | R14 (LR) | Endereço de retorno |
| **ARM** | R15 (PC) | Contador de programa |
| **x86** | EAX | Acumulador (resultados) |
| **x86** | EBX | Base (ponteiro) |
| **x86** | ECX | Contador (loops) |
| **x86** | EDX | Dados (operações) |

### 4.2 Exemplo: Programa simples

<pre>
Instrução          | O que faz                     | Estado dos registradores
-------------------|-------------------------------|--------------------------
MOV R0, #5         | R0 = 5                        | R0=5, R1=0, R2=0
MOV R1, #3         | R1 = 3                        | R0=5, R1=3, R2=0
ADD R2, R0, R1     | R2 = R0 + R1 = 5 + 3 = 8    | R0=5, R1=3, R2=8
SUB R0, R2, R1     | R0 = R2 - R1 = 8 - 3 = 5    | R0=5, R1=3, R2=8
CMP R0, R1         | Compara R0 e R1              | Flags atualizadas
BEQ fim            | Se R0 = R1, pula para "fim" | (salta se iguais)
</pre>

A UC usa **endereços** para selecionar quais registradores ler ou escrever:

<pre>

Campos da instrução:
- ${\color{white}\text{Opcode: ADD (soma)}}$
- ${\color{white}\text{Destino: R0 (endereço 00000)}}$
- ${\color{white}\text{Operando 1: R1 (endereço 00001)}}$
- ${\color{white}\text{Operando 2: R2 (endereço 00010)}}$

A UC:
1. ${\color{white}\text{Lê R1 e R2 do banco de registradores.}}$

3. ${\color{white}\text{Escreve o resultado em R0.}}$ 
</pre>


## 6. Vantagens dos Registradores

### 6.1 Velocidade

Os registradores são o **armazenamento mais rápido** da hierarquia de memória:

| Nível | Tempo de acesso | Capacidade |
|-------|-----------------|------------|
| Registradores | ~1 ciclo | ~1 KB |
| Cache L1 | ~2-4 ciclos | ~32 KB |
| Cache L2 | ~10 ciclos | ~256 KB |
| RAM | ~50-100 ns | ~16 GB |

### 6.2 Eficiência

- Operações com registradores são **muito mais rápidas** que com memória.
- Instruções que usam registradores são **menores** (ocupam menos espaço).
- Registradores **reduzem o tráfego** no barramento de dados.

### 6.3 Flexibilidade

- Qualquer registrador pode armazenar qualquer dado.
- O programador (ou compilador) decide como usar os registradores.
- Diferentes convenções de chamada usam registradores de maneiras diferentes.

## 8. Resumo

> **"Os Registradores de Uso Geral são o armazém de dados da CPU — a área de trabalho onde os dados são mantidos durante o processamento. Eles são extremamente rápidos (acesso em 1 ciclo), flexíveis (podem armazenar qualquer dado) e essenciais para o desempenho do processador. Enquanto registradores especializados (PC, IR, MAR, MBR) têm funções fixas, os registradores de uso geral são o 'espaço de trabalho' do programador, onde operandos são colocados, operações são executadas e resultados são armazenados. Em arquiteturas modernas, há de 8 a 32 registradores de uso geral, organizados em um banco de registradores. Sem eles, a CPU teria que acessar a memória a cada operação — o que seria milhares de vezes mais lento."**
