# ESPECULAÇÃO

## 1. INTRODUÇÃO

Na aula anterior, estudamos a execução fora de ordem — como a CPU reordena instruções para maximizar o uso das unidades funcionais. Vimos que a CPU executa instruções quando elas estão prontas, independentemente da ordem do programa.<br><br>

Mas há um tipo de instrução que apresenta um desafio ainda maior: os **saltos condicionais (branches)**. Quando a CPU encontra um branch, ela não sabe qual instrução executar em seguida até avaliar a condição. Em um pipeline out-of-order, isso é especialmente problemático — a CPU pode ter várias instruções aguardando, e não sabe qual caminho seguir.<br><br>

A solução é a **especulação**. Em vez de esperar a condição ser avaliada, a CPU **adivinha** qual caminho será tomado (usando branch prediction) e **executa as instruções desse caminho antecipadamente**. Se a previsão estiver correta, o ganho de desempenho é enorme. Se estiver errada, a CPU descarta o trabalho e recomeça.<br><br>

Imagine que você está em um restaurante e o garçom pergunta: "O senhor vai querer a carne ou o peixe?" Em vez de esperar você decidir, ele já começa a preparar ambos. Quando você decide, ele descarta o que não foi pedido e serve o que você escolheu. É arriscado (desperdiça comida se errar), mas se acertar, o serviço é muito mais rápido. A especulação funciona exatamente assim.<br><br>

Nesta aula, vamos estudar a especulação: o que é, como funciona, quais são seus componentes (ROB com especulação, checkpoint), e como ela transforma o desempenho dos processadores modernos.

## 2. O QUE É ESPECULAÇÃO?

### 2.1 Definição

> "Especulação é uma técnica onde a CPU executa instruções antes de saber se um salto condicional será tomado ou não, baseando-se em uma previsão. Se a previsão estiver correta, o desempenho aumenta. Se estiver errada, a CPU descarta os resultados e recomeça."

### 2.2 Características principais

| Característica | Descrição |
|---------|----------|
| **O que faz** | Executa instruções de um caminho previsto antes da confirmação |
| **Base** | Branch prediction (previsão de saltos) |
| **Componente principal** | ROB (Reorder Buffer) com capacidade de rollback |
| **Vantagem** | Mantém o pipeline ocupado, esconde latências |
| **Risco** | Previsão errada → desperdício de energia e ciclos |

### 2.3 Analogia

A especulação é como um **jogador de xadrez que antecipa os movimentos do adversário**. Ele calcula várias possibilidades e prepara respostas. Se o adversário fizer o movimento esperado, ele já está pronto. Se fizer outro, ele descarta os planos anteriores e recalcula.

## 3. POR QUE ESPECULAR?

### 3.1 O problema dos branches em out-of-order

Em um processador out-of-order, a CPU pode ter muitas instruções em execução simultaneamente. Quando encontra um branch, ela precisa decidir:

1. **Esperar a condição ser avaliada** → pipeline stall, perda de desempenho.
2. **Especular** → executar o caminho previsto, mantendo o pipeline ocupado.

**O custo de esperar:**
- Em um pipeline de 15 estágios, esperar um branch custa ~15 ciclos.
- Em um processador que executa 4 instruções por ciclo, isso significa ~60 instruções perdidas.

**O custo de especular errado:**
- Descartar instruções do caminho errado (~15 ciclos de trabalho perdido).
- Mas se a previsão estiver correta, o ganho é enorme.

### 3.2 O equilíbrio: acurácia vs custo

| Acurácia do branch predictor | Custo médio por branch |
|---------|----------|
| 50% (aleatório) | 7.5 ciclos |
| 80% | 3 ciclos |
| 90% | 1.5 ciclos |
| 95% | 0.75 ciclos |
| 99% | 0.15 ciclos |

**Conclusão:** Com preditores modernos (>95% de acurácia), a especulação é quase sempre vantajosa.

## 5. CHECKPOINT E ROLLBACK

### 5.1 O que é um checkpoint?

Um **checkpoint** é um "ponto de restauração" — o estado da CPU antes de uma instrução especulativa. Se a especulação falhar, a CPU pode restaurar o estado anterior.

**O checkpoint inclui:**
- Estado dos registradores
- Estado do PC (Program Counter)
- Estado do ROB
- Estado das unidades funcionais

### 5.2 Como funciona o rollback

Quando a previsão está errada:

1. **Detecta o erro:** A condição do branch é avaliada e a previsão está errada.
2. **Flush (descartar):** Todas as instruções especulativas são descartadas do pipeline.
3. **Rollback:** A CPU restaura o estado do checkpoint.
4. **Recomeça:** A CPU busca a instrução correta (o outro caminho).

**Custo do rollback:**
- 10-20 ciclos (dependendo do pipeline).
- Energia desperdiçada nas instruções descartadas.

### 5.3 Checkpoint em processadores modernos

| Processador | Checkpoints | Tamanho do ROB |
|---------|---------|---------|
| **Intel Core i9** | 2-3 checkpoints ativos | ~224 entradas |
| **AMD Ryzen** | 2 checkpoints ativos | ~192 entradas |
| **ARM Cortex-A76** | 1-2 checkpoints | ~128 entradas |

## 6. ESPECULAÇÃO DE MEMÓRIA

### 6.1 O que é especulação de memória?

A especulação de memória é uma técnica onde a CPU **especula que um load (leitura de memória) não vai conflitar com um store (escrita) anterior**, e executa o load antes do store.

**Exemplo:**

<pre style="color: white; background: #0a0f1e; padding: 1rem; border-radius: 8px; font-family: monospace; font-size: 0.85rem; border: 1px solid rgba(255,255,255,0.08); overflow-x: auto;">
I1: STR R1, [R2]     ; Store (escreve na memória)
I2: LDR R3, [R4]     ; Load (lê da memória)
</pre>

Se R2 e R4 apontarem para endereços diferentes, o load pode ser executado antes do store sem problemas. Se apontarem para o mesmo endereço, o load lê o valor **antigo** (antes do store) — o que pode estar errado.

**Solução:** A CPU especula que os endereços são diferentes. Se estiver errada, faz rollback.

### 6.2 Load-Store Queue

A CPU mantém uma fila de loads e stores para gerenciar a especulação de memória:

| Estrutura | Função |
|---------|----------|
| **Load Queue** | Armazena loads especulativos |
| **Store Queue** | Armazena stores especulativos |
| **Aging** | Ordena as operações por idade |

**Quando um load encontra um store anterior com mesmo endereço:**
- Se a previsão estiver correta, o load lê do store (forwarding).
- Se a previsão estiver errada, o load faz rollback (descarta).

## 7. VANTAGENS E DESVANTAGENS

### 7.1 Vantagens

| Vantagem | Explicação |
|---------|----------|
| **Mantém o pipeline ocupado** | Instruções executam mesmo durante branches |
| **Esconde latências** | Loads e operações longas são escondidas |
| **Maior throughput** | Mais instruções por ciclo |
| **Base para outras otimizações** | Value prediction, prefetching |

### 7.2 Desvantagens

| Desvantagem | Explicação |
|---------|----------|
| **Desperdício de energia** | Instruções descartadas gastam energia |
| **Complexidade** | Checkpoints, rollback, recuperação de exceções |
| **Área do chip** | ROB, filas de load/store, checkpoints |
| **Risco de segurança** | Ataques Spectre/Meltdown exploram especulação |

## 8. ESPECULAÇÃO E SEGURANÇA

### 8.1 O problema: Ataques Spectre e Meltdown

Em 2018, foram descobertos ataques que exploram a especulação para vazar informações.

**Spectre:**
1. O atacante treina o branch predictor para seguir um caminho específico.
2. A CPU executa especulativamente instruções que leem dados proibidos.
3. Os dados são armazenados em cache (efeito colateral).
4. O atacante mede o tempo de acesso ao cache para descobrir os dados.

**Meltdown:**
1. O atacante tenta ler memória do kernel (protegida).
2. A CPU executa especulativamente, mesmo que a instrução seja inválida.
3. O resultado é armazenado em cache.
4. O atacante mede o tempo para descobrir os dados.

### 8.2 Mitigações

| Mitigação | Descrição |
|---------|----------|
| **Barreiras de especulação** | Impedem especulação em instruções sensíveis |
| **Cache flushing** | Limpa o cache após especulação |
| **Kernel Page Table Isolation (KPTI)** | Isola tabelas de páginas do kernel |
| **Microcode updates** | Atualizações de firmware para corrigir |

> A especulação é uma aposta que a CPU faz: aposta que o branch predictor está certo, executa instruções antecipadamente, e depois verifica. Se ganhou, o desempenho dispara. Se perdeu, descarta o trabalho e recomeça. É uma técnica arriscada, mas com preditores modernos (>95% de acurácia), o risco vale a pena. A especulação é uma das técnicas mais importantes da arquitetura moderna. Ela permite que processadores mantenham o pipeline ocupado mesmo na presença de branches, escondendo latências e maximizando o throughput. No entanto, ela também introduz complexidade e riscos de segurança, como demonstrado pelos ataques Spectre e Meltdown.
