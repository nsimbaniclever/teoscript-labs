# TÉCNICAS DE MITIGAÇÃO

## 1. INTRODUÇÃO

Nas últimas três aulas, estudamos os três tipos de conflitos que podem parar o pipeline: **data hazards** (dependência de dados), **structural hazards** (concorrência por recursos) e **control hazards** (saltos condicionais). Vimos que cada um deles pode causar stalls — pausas que reduzem o desempenho do processador.<br><br>

Mas o pipeline não precisa sofrer passivamente com esses conflitos. Existem técnicas poderosas para **mitigar** (reduzir ou eliminar) esses problemas. As três principais são: **forwarding**, **stalls** e **branch prediction**.<br><br>

- **Forwarding** (encaminhamento) resolve a maioria dos data hazards enviando dados diretamente entre estágios.
- **Stalls** (pausas) são usados quando forwarding não é possível (ex: após um load).
- **Branch prediction** (predição de saltos) resolve control hazards, prevendo o comportamento de branches.<br><br>

Juntas, essas técnicas mantêm o pipeline o mais cheio possível, maximizando o throughput e o desempenho do processador.<br><br>

Imagine que você é um maestro regendo uma orquestra. Quando um músico erra uma nota (data hazard), você não para a orquestra inteira — você redireciona o som (forwarding) para que ele seja corrigido rapidamente. Quando um músico precisa trocar de partitura (structural hazard), você dá um pequeno intervalo (stall). Quando o maestro precisa decidir qual música tocar em seguida (control hazard), ele faz uma previsão baseada no repertório anterior (branch prediction). O resultado é uma apresentação fluida e contínua.<br><br>

Nesta aula, vamos estudar essas três técnicas de mitigação: como funcionam, quando são usadas, e como juntas mantêm o pipeline em alta performance.

## 2. FORWARDING (ENCAMINHAMENTO) — A SOLUÇÃO PARA DATA HAZARDS

### 2.1 Definição

> "Forwarding (ou bypass) é uma técnica onde o resultado de uma operação é enviado diretamente da saída de um estágio do pipeline para a entrada de outro, sem esperar a escrita no registrador, eliminando ou reduzindo stalls causados por data hazards."

- **MEM → EX:** Dado da memória vai direto para a ULA.
- **WB → ID:** Resultado vai direto para o banco de registradores.

### 2.4 Quando o forwarding NÃO funciona

O forwarding não funciona em todas as situações. O caso mais comum é o **load-use hazard**:

## 3. STALLS (PAUSAS) — QUANDO O PIPELINE PRECISA ESPERAR

### 3.1 Definição

> "Stall (ou bubble) é uma técnica onde o pipeline é temporariamente pausado, inserindo ciclos vazios (bolhas) para resolver conflitos que não podem ser resolvidos por forwarding."

### 3.2 Quando os stalls são usados?

| Situação | Por que stall é necessário |
|---------|----------|
| **Load-use hazard** | O dado do load só está disponível após MEM |
| **Conflito estrutural** | Dois estágios precisam do mesmo recurso |
| **Conflito de controle** | Branch sem predição (ou previsão errada) |
| **Operações complexas** | Divisão pode levar vários ciclos |

### 3.3 Como um stall funciona

1. A CPU detecta que um conflito não pode ser resolvido por forwarding.
2. A CPU congela (stall) os estágios anteriores ao estágio afetado.
3. A CPU insere uma "bolha" (bubble) no pipeline — um estágio vazio que não faz nada.
4. Quando o conflito é resolvido, o pipeline prossegue.

### 3.4 O custo dos stalls

| Tipo de stall | Ciclos perdidos |
|---------|----------|
| **Load-use hazard** | 1 ciclo |
| **Structural hazard** | 1-2 ciclos |
| **Control hazard (sem predição)** | 2-3 ciclos |
| **Control hazard (previsão errada)** | 2-3 ciclos |
| **Divisão (operação complexa)** | Vários ciclos |

## 4. BRANCH PREDICTION — A SOLUÇÃO PARA CONTROL HAZARDS

### 4.1 Definição

> "Branch prediction é uma técnica onde a CPU tenta prever o resultado de um salto condicional antes de avaliar a condição, permitindo que o pipeline continue buscando instruções sem stalls."

### 4.2 Tipos de branch prediction

| Tipo | Como funciona | Acurácia |
|---------|---------|---------|
| **Estática** | Sempre assume o mesmo comportamento | ~50-70% |
| **Dinâmica (1-bit)** | Lembra o último resultado do salto | ~80-85% |
| **Dinâmica (2-bit)** | Lembra o histórico com estados de confiança | ~90-95% |
| **Tournament** | Combina múltiplos preditores | ~95-98% |
| **Neural** | Usa redes neurais | ~98-99% |

### 4.4 Branch Target Buffer (BTB)

O **BTB** armazena o endereço alvo de cada salto, permitindo que a CPU busque a instrução correta imediatamente.

**Estrutura do BTB:**

<details>
<summary> **Branch Target Buffer (BTB)**</summary>
    <pre style="color: white; background: #0a0f1e; padding: 1rem; border-radius: 8px; font-family: monospace; font-size: 0.85rem; border: 1px solid rgba(255,255,255,0.08); overflow-x: auto;">
┌─────────────────────────────────────────────────────────────┐
│   Endereço do Salto  │  Endereço Alvo  │  Histórico       │
│   (PC)               │  (Target)       │  (2 bits)        │
├─────────────────────────────────────────────────────────────┤
│   0x1000             │  0x2000         │  11 (Tomado)     │
│   0x2004             │  0x3000         │  00 (Não Tomado) │
│   0x3008             │  0x1000         │  10 (Tomado)     │
└─────────────────────────────────────────────────────────────┘
    </pre>
</details>

**Como funciona:**
1. A CPU consulta o BTB com o PC da instrução atual.
2. Se houver um salto, a CPU obtém o endereço alvo e a previsão.
3. A CPU busca a instrução no endereço alvo (se previsto tomado).
4. Se a previsão estiver errada, a CPU descarta as instruções e atualiza o BTB.

### 5.2 Decisões do pipeline

| Situação | Técnica usada |
|---------|----------|
| Data hazard (ADD → SUB) | Forwarding |
| Data hazard (LDR → ADD) | Stall + Forwarding |
| Structural hazard | Stall |
| Control hazard (branch) | Branch Prediction |
| Control hazard (previsão errada) | Flush (descartar) + Stall |

   ↓

## 6. APLICAÇÕES REAIS

| Técnica | Usada em | Exemplo |
|---------|---------|---------|
| **Forwarding** | Todos os processadores modernos | Intel Core, AMD Ryzen, ARM |
| **Stalls** | Todos os processadores | Quando forwarding não é possível |
| **Branch Prediction** | Processadores de alto desempenho | Intel Core, AMD Ryzen |
| **BTB** | Processadores de alto desempenho | Intel Core, AMD Ryzen |
| **Delayed Branch** | Processadores RISC antigos | SPARC, MIPS (mais antigos) |

**Exemplo prático:** Um processador Intel Core i9 usa forwarding para resolver ~80% dos data hazards, stalls para ~10% (load-use), e branch prediction para ~95% dos control hazards.

> Forwarding, stalls e branch prediction são as três ferramentas que mantêm o pipeline funcionando apesar dos conflitos. Forwarding resolve a maioria dos data hazards enviando dados diretamente entre estágios. Stalls são usados quando forwarding não é possível. Branch prediction resolve control hazards, prevendo o comportamento de saltos com alta acurácia. Juntas, essas técnicas permitem que o pipeline opere próximo ao seu máximo teórico, entregando o desempenho que esperamos dos processadores modernos. As três técnicas de mitigação — forwarding, stalls e branch prediction — são a base do pipeline moderno. Elas trabalham juntas para manter o pipeline ocupado, minimizando stalls e maximizando o throughput. Forwarding resolve data hazards com zero custo, stalls resolvem o que forwarding não pode, e branch prediction resolve control hazards com alta acurácia. Sem essas técnicas, os processadores modernos seriam muito mais lentos e menos eficientes.
