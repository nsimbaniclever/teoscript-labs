# ENDEREÇAMENTO IMEDIATO

## 1. INTRODUÇÃO

Nas aulas anteriores, estudamos as instruções que a CPU executa: aritméticas, lógicas, de transferência e de desvio. Vimos como a CPU soma, subtrai, compara, carrega da memória e salta para diferentes partes do código. Mas há uma pergunta fundamental: **como a CPU sabe onde estão os dados que precisa processar?**<br><br>

A resposta está nos **modos de endereçamento**. Cada instrução precisa especificar de onde vêm os dados (operandos) e para onde vão os resultados. O modo de endereçamento define exatamente como a CPU interpreta os operandos da instrução.<br><br>

O primeiro e mais simples modo de endereçamento é o **endereçamento imediato**. Neste modo, o valor do operando é fornecido **diretamente na própria instrução**, como uma constante literal. É o modo mais rápido porque a CPU não precisa buscar o dado em lugar nenhum — ele já está na instrução.<br><br>

Imagine que você está cozinhando e uma receita diz "adicione 3 colheres de sal". O número 3 está escrito na receita (instrução) — você não precisa ir buscar em outro lugar. Esse é o endereçamento imediato.<br><br>

Nesta aula, vamos estudar o endereçamento imediato: o que é, como funciona, quando é usado, e quais são suas vantagens e limitações.

## 2. O QUE É ENDEREÇAMENTO IMEDIATO?

### 2.1 Definição

> "Endereçamento imediato é um modo onde o operando é um valor literal (constante) incluído na própria instrução, sendo acessado diretamente sem necessidade de buscar o dado na memória ou em registradores."

### 2.2 Características principais

| Característica | Descrição |
|---------|----------|
| **Onde está o dado** | Dentro da própria instrução |
| **Velocidade** | A mais rápida (acesso imediato) |
| **Uso** | Constantes, valores fixos, inicializações |
| **Limitação** | Valores limitados pelo tamanho do campo imediato da instrução |

### 2.3 Sintaxe

Em Assembly, valores imediatos são geralmente precedidos por `#`:

| Arquitetura | Sintaxe | Exemplo |
|---------|---------|---------|
| **ARM** | `#valor` | `ADD R1, R2, #5` |
| **x86** | `valor` | `ADD EAX, 5` |
| **MIPS** | `#valor` | `addi $t0, $t1, 5` |

## 3. COMO FUNCIONA O ENDEREÇAMENTO IMEDIATO?

### 3.1 Estrutura da instrução

Uma instrução com endereçamento imediato contém:

[CÓDIGO DA OPERAÇÃO] [REGISTRADOR DESTINO] [REGISTRADOR FONTE] [VALOR IMEDIATO]
</pre>

**Exemplo (ARM):** `ADD R1, R2, #5`

<pre style="color: white; background: #0a0f1e; padding: 1rem; border-radius: 8px; font-family: monospace; font-size: 0.85rem; border: 1px solid rgba(255,255,255,0.08); overflow-x: auto;">
ADD    R1,    R2,    #5
Opcode Destino Fonte  Imediato
</pre>

### 3.2 Como a CPU executa

1. A CPU busca a instrução da memória.
2. A CPU decodifica a instrução.
3. A CPU extrai o valor imediato da instrução.
4. A CPU executa a operação usando o valor imediato.
5. **Não há acesso à memória ou a registradores para buscar o operando.**

### 3.4 Exemplo prático

**Instrução:** `ADD R1, R2, #10`

**Antes:** R2 = 5
**Depois:** R1 = 5 + 10 = 15

O valor 10 foi retirado diretamente da instrução.

## 5. LIMITAÇÕES DO ENDEREÇAMENTO IMEDIATO

### 5.1 Tamanho limitado do campo imediato

O campo imediato na instrução tem um número fixo de bits. Isso limita o tamanho do valor que pode ser usado.

| Arquitetura | Tamanho do imediato | Valor máximo |
|---------|---------|---------|
| **ARM (32 bits)** | 8-12 bits | 0-4095 |
| **x86 (32 bits)** | 8-32 bits | 0-4.294.967.295 |
| **MIPS (32 bits)** | 16 bits | 0-65.535 |

### 5.2 Exemplo: ARM e o campo imediato de 8 bits

Em ARM, o campo imediato tem 8 bits (0-255), mas com rotação para valores maiores.

**Valores imediatos válidos em ARM:**
- `#0` a `#255` (diretamente)
- `#256` a `#4095` (através de rotação)
- Nem todos os valores entre 256 e 4095 são válidos.

### 5.3 Como contornar a limitação

Para valores maiores que o campo imediato permite, é necessário usar outras técnicas:

1. **Carregar de uma constante na memória:**

LDR R1, =0x12345678   ; Carrega uma constante grande da memória
</pre>

2. **Carregar em duas etapas:**

## 6. VANTAGENS DO ENDEREÇAMENTO IMEDIATO

### 6.1 Velocidade

O endereçamento imediato é o mais rápido porque:
- **Não acessa a memória** (como load/store)
- **Não acessa registradores** para buscar o operando (como registro)
- O valor está **dentro da instrução** que já foi buscada

### 6.2 Simplicidade

Não há necessidade de calcular endereços ou acessar outras estruturas. A CPU simplesmente extrai o valor da instrução.

### 6.3 Eficiência de código

Muitas operações usam constantes pequenas:
- Incrementar (`ADD R1, R1, #1`)
- Zerar (`MOV R1, #0`)
- Comparar (`CMP R1, #10`)
- Máscaras (`AND R1, R1, #0xFF`)

## 7. APLICAÇÕES REAIS

| Aplicação | Como usa endereçamento imediato |
|---------|----------|
| **Contadores de loop** | `ADD R1, R1, #1` (incremento) |
| **Comparações** | `CMP R1, #10` (comparar com constante) |
| **Inicialização** | `MOV R1, #0` (zerar registrador) |
| **Máscaras** | `AND R1, R1, #0x0F` (extrair bits) |
| **Deslocamentos** | `LSL R1, R2, #3` (multiplicar por 8) |
| **Acesso a periféricos** | Configurar bits com `OR R1, R1, #0x01` |

**Exemplo prático:** Um programa que conta de 0 a 10 usa constantes imediatas para o contador e o limite.

> O endereçamento imediato é o modo mais rápido e simples de especificar um operando: o valor está literalmente na instrução. Embora limitado pelo tamanho do campo imediato, é essencial para constantes pequenas, contadores, comparações e máscaras. O endereçamento imediato é a base de muitas operações cotidianas em Assembly. Incrementar um contador, comparar um valor com zero, aplicar uma máscara — todas essas operações usam constantes imediatas. Sua simplicidade e velocidade o tornam indispensável, mesmo com sua limitação de tamanho.
