# INSTRUÇÕES DE DESVIO

## 1. INTRODUÇÃO

Nas últimas três aulas, estudamos as instruções que a CPU executa: aritméticas (somar, subtrair), lógicas (AND, OR, XOR) e de transferência (load, store). Vimos como a CPU manipula dados, faz cálculos e acessa a memória. Mas há uma pergunta fundamental: **como a CPU decide qual instrução executar em seguida?**<br><br>

Normalmente, a CPU executa instruções em sequência — uma após a outra. Mas a vida não é linear. Muitas vezes precisamos que o computador tome decisões: "se X for maior que Y, faça A; senão, faça B". Ou precisamos repetir um bloco de código várias vezes (loops). É aí que entram as **instruções de desvio**.<br><br>

Instruções de desvio são como **bifurcações em uma estrada**. Sem elas, o programa seria uma linha reta, sempre executando as mesmas instruções na mesma ordem. Com elas, o programa pode tomar decisões, repetir ações e saltar para diferentes partes do código.<br><br>

Nesta aula, vamos estudar as instruções de desvio em Assembly: JMP (saltos incondicionais), BEQ, BNE, BLT, BGT (saltos condicionais), e como eles usam as flags da ALU para tomar decisões. Vamos entender como loops e condicionais funcionam no nível mais baixo da computação.

## 2. O QUE SÃO INSTRUÇÕES DE DESVIO?

### 2.1 Definição

> "Instruções de desvio são operações que alteram o fluxo de execução do programa, permitindo que a CPU execute instruções em uma ordem diferente da sequencial, seja incondicionalmente (jump) ou baseado em condições (branch)."

### 2.2 Tipos de instruções de desvio

| Tipo | Descrição | Exemplo | Significado |
|---------|---------|---------|---------|
| **JMP** | Salto incondicional | `JMP label` | Vai para a instrução em 'label' |
| **BEQ** | Branch if Equal | `BEQ label` | Vai para 'label' se Z = 1 |
| **BNE** | Branch if Not Equal | `BNE label` | Vai para 'label' se Z = 0 |
| **BLT** | Branch if Less Than | `BLT label` | Vai para 'label' se N ≠ V |
| **BGT** | Branch if Greater Than | `BGT label` | Vai para 'label' se Z = 0 e N = V |
| **BLE** | Branch if Less or Equal | `BLE label` | Vai para 'label' se Z = 1 ou N ≠ V |
| **BGE** | Branch if Greater or Equal | `BGE label` | Vai para 'label' se N = V |

### 2.3 Analogia

As instruções de desvio são como **placas de trânsito** em uma estrada:

- **JMP:** "Siga em frente" (sempre vá para o próximo ponto).
- **BEQ:** "Se o semáforo estiver verde, vire à direita" (se a condição for verdadeira).
- **BNE:** "Se o semáforo estiver vermelho, vire à esquerda" (se a condição for falsa).
- **BLT/BGT:** "Se a velocidade for menor/maior que o limite, tome uma ação."

## 3. COMO A CPU EXECUTA UM DESVIO?

### 3.1 O Program Counter (PC)

O **Program Counter (PC)** é um registrador especial que contém o endereço da próxima instrução a ser executada. Em uma execução sequencial:

1. A CPU busca a instrução apontada pelo PC.
2. A CPU executa a instrução.
3. O PC é incrementado para apontar para a próxima instrução.

### 3.2 Como funciona um salto

Quando a CPU executa uma instrução de desvio:

1. A CPU decodifica a instrução (ex: `JMP label`).
2. A CPU calcula o endereço da 'label'.
3. A CPU **substitui o valor do PC** pelo endereço da label.
4. A próxima instrução buscada será a da label.

**Efeito:** O fluxo de execução "salta" para outra parte do programa.

## 5. SALTOS CONDICIONAIS — BASEADOS NAS FLAGS

### 5.1 As flags da ALU

A ALU (Unidade Lógica e Aritmética) gera flags após cada operação:

| Flag | Descrição | Quando é ativada |
|---------|---------|---------|
| **Z (Zero)** | Resultado é zero | Resultado = 0 |
| **N (Negative)** | Resultado é negativo | Resultado < 0 |
| **C (Carry)** | Houve "vai-um" | Overflow em operações sem sinal |
| **V (Overflow)** | Estouro de sinal | Overflow em operações com sinal |

### 5.2 Como as instruções condicionais funcionam

1. Uma instrução aritmética ou lógica é executada (ex: `SUB R1, R2, R3`).
2. As flags são atualizadas com base no resultado.
3. Uma instrução de desvio condicional verifica as flags.
4. Se a condição for satisfeita, o salto é executado.
5. Se a condição não for satisfeita, a execução continua sequencialmente.

### 5.3 Tabela de instruções condicionais

| Instrução | Condição | Flags | Significado |
|---------|---------|---------|---------|
| **BEQ** | Igual | Z = 1 | Branch if Equal |
| **BNE** | Diferente | Z = 0 | Branch if Not Equal |
| **BLT** | Menor que | N ≠ V | Branch if Less Than |
| **BGT** | Maior que | Z = 0 e N = V | Branch if Greater Than |
| **BLE** | Menor ou igual | Z = 1 ou N ≠ V | Branch if Less or Equal |
| **BGE** | Maior ou igual | N = V | Branch if Greater or Equal |
| **BPL** | Positivo | N = 0 | Branch if Plus |
| **BMI** | Negativo | N = 1 | Branch if Minus |
| **BCS** | Carry set | C = 1 | Branch if Carry Set |
| **BCC** | Carry clear | C = 0 | Branch if Carry Clear |

## 7. COMPARAÇÃO (CMP) — O CORAÇÃO DOS DESVIOS CONDICIONAIS

### 7.1 O que é CMP?

A instrução **CMP** (Compare) compara dois valores subtraindo-os e atualizando as flags, **sem armazenar o resultado**.

**Sintaxe:** `CMP R1, R2` (compara R1 e R2)

**Efeito:** Subtrai R2 de R1 (R1 - R2) e atualiza as flags Z, N, C, V.

### 7.2 Exemplo: Comparação

<pre style="color: white; background: #0a0f1e; padding: 1rem; border-radius: 8px; font-family: monospace; font-size: 0.85rem; border: 1px solid rgba(255,255,255,0.08); overflow-x: auto;">
CMP R1, R2        ; Calcula R1 - R2, atualiza flags

BEQ igual         ; Se R1 == R2, salta
BNE diferente     ; Se R1 != R2, salta
BLT menor         ; Se R1 < R2, salta
BGT maior         ; Se R1 > R2, salta
</pre>

### 7.3 Tabela: Flags após CMP

| Comparação | Z | N | C | V |
|---------|---------|---------|---------|---------|
| R1 = R2 | 1 | 0 | 0 | 0 |
| R1 > R2 (sem sinal) | 0 | 0 | 1 | 0 |
| R1 < R2 (sem sinal) | 0 | 1 | 0 | 0 |
| R1 > R2 (com sinal) | 0 | 0 | — | 0 |
| R1 < R2 (com sinal) | 0 | 1 | — | 0 |

> Instruções de desvio são o que tornam os programas verdadeiramente inteligentes. JMP permite saltos incondicionais; BEQ, BNE, BLT, BGT e outras permitem decisões baseadas em comparações. Combinadas com CMP e as flags da ALU, elas implementam if/else, loops, switch/case e toda a lógica condicional que faz um programa parecer 'vivo'. Sem instruções de desvio, os programas seriam lineares — executando sempre a mesma sequência de instruções. Com elas, os programas podem tomar decisões, repetir ações, saltar para diferentes partes do código, e reagir a entradas do usuário e condições do sistema. Elas são o coração da lógica de programação no nível mais baixo.
